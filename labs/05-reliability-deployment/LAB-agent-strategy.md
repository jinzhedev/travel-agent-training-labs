# Lab 05 备选：预算终态与无进展停止

先完成 [任务预算主实验](LAB.md#实验二模型自主调用与整次任务预算)。本实验不要求所有学员开发插件，只有需要控制 Agent 内部循环时再做。

## 默认 Strategy 覆盖到哪里

本机预试使用 Dify 官方 Agent 插件 `0.0.47` 的 FunctionCalling 实现。该版本按轮调用模型，同一轮的工具逐个执行，`maximum_iterations` 限制模型循环轮次。

它没有整次业务任务的付费工具累计预算，也没有读取业务进展后硬停止的规则。主实验已经在执行端补了累计预算。默认 Strategy 收到 `tool_budget_exhausted` 后，模型可能选择结束，也可能继续尝试；以本次 trace 为准。

不要把这称为“默认工具并发失控”。工具数量、模型轮次、同时在途的调用数是不同指标。

## 先确认是否需要定制

完成下面的对照：

1. 保持主实验的 5 次工具预算。
2. 记录达到额度后实际还有多少模型调用、拒绝的工具请求，以及最终回答。
3. 主实验的 Prompt 已包含收到停止结果后不再请求工具的规则。检查 trace 是否遵守；如果调整这条规则，只改这一项，再用新任务运行同一题。
4. 如果模型自然停止且已满足业务要求，记录不需要为这个案例开发 Strategy。Prompt 改善不替代执行端的预算硬限制。

## 最小改动：预算耗尽后结束循环

从课堂锁定的官方插件源码复制到独立插件项目，使用新的插件身份和版本，不覆盖系统安装的插件。按该版本真实的工具执行与 Observation 读取位置插入检查；安装、签名和导入过程遵循课堂 Dify 的插件开发环境。

循环规则如下，这是实现要求，不是可直接导入 Dify 的插件代码：

```text
逐个处理模型提出的调用
  → 调用执行端
  → 读取结构化结果
  → stop_reason=tool_budget_exhausted 或 task_cancelled
      → 不再处理本轮剩余工具
      → 不再发起下一轮模型请求
      → 输出 incomplete、停止原因、已完成和未完成事项
  → 其他结果进入下一次决策
```

必须通过执行端先判断预算，Strategy 不持有另一套可以重置的业务额度。即使插件失效，执行端仍然拒绝越限调用。

硬停止输出示例：

```json
{
  "status": "incomplete",
  "stop_reason": "tool_budget_exhausted",
  "completed": ["已成功取得五次查询结果"],
  "unresolved": ["尚未完成其余候选的比较"],
  "task_id": "<执行端返回的任务ID>"
}
```

`completed` 必须来自实际 Observation，不能使用上面的示例文字冒充本次结果。Answer 可展示这个终态，不再调用 LLM 将其润色成“全部完成”。

## 再考虑无进展检测

确有重复循环时，比较工具名称、规范化参数、有效 Observation 和相关业务状态。达到课堂阈值后，在下一次工具执行前以 `no_progress` 结束。

| 情况 | 处理 |
| --- | --- |
| 同样参数、同样业务证据、状态未变 | 累计无进展次数 |
| 参数修正后取得新证据 | 允许继续，清除连续无进展计数 |
| 工具名字不同，但仍返回相同业务信息 | 不能仅因换工具名视为进展 |
| 订单从 pending 变为 confirmed | 属于状态进展 |

不要对整个响应直接求 hash：`used_calls`、时间戳、request ID 等每次都会变化，但不代表取得新业务证据。对每种工具明确抽取哪些业务字段。

调用指纹只辅助检测循环，不代替业务 operation 身份，也不把正常状态轮询直接判成重复写。

## 验证与停止条件

使用相同模型和任务，在默认 Strategy 与定制版本分别保存真实 trace：

- 预算耗尽前，有效查询能执行；
- 首次收到预算终态后，本轮剩余工具与下一轮模型都不再执行；
- 取消终态同样停止循环；
- 如果增加无进展检测，参数修正和有效状态变化不能被误拦截；
- 终态明确哪些目标未完成，执行端累计工具次数仍不超过 5。

记录插件版本、阈值、模型轮次、成功与拒绝的工具请求数、Token、耗时。只有插件实际安装并运行后，才能标记为已验证；只读源码或填写伪代码保持 `not_run`。
