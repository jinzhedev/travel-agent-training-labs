# Tool Calling 评测集 v1

本评测集包含 40 条中文文旅请求，已从旧版虚构城市案例迁移到厦门，并把每条样本内重复的工具定义移到公共工具目录。

覆盖类型：

- 单工具、并行工具、结果依赖首步和条件首步；
- 缺参数澄清、无需工具回答和拒绝调用；
- 副作用确认、权限不足、提示词注入和调用预算；
- 相似工具选择、参数格式和工具集合召回。

链路效率实验固定使用 `TOOL-009/024/025/026/033/038` 六条，不复制第二份金标：

- `TOOL-009/025`：无依赖只读调用，可以并行；
- `TOOL-038`：行程参数依赖无障碍景点搜索返回的 `poi_id`，只执行当前可确定的首步；
- `TOOL-024`：后续参数依赖天气与景点结果，只执行当前可确定的首步；
- `TOOL-033`：后续分支取决于预报中的风速和阵风，只执行当前可确定的首步；
- `TOOL-026`：已知对象直接查询，用于检查最短有效链。

每条金标记录可信权限、是否允许副作用、审批标识、期望 action、候选工具集合、调用顺序、参数和最大调用次数。少数语义完全等价的调用可写入 `accepted_call_variants`；例如 `TOOL-026` 的 `poi.get_details` 既接受省略 `city`，也接受显式传入 `city=厦门`，两者都必须保持单次调用。需要登录用户或当前业务对象的样本把它们记录为独立的可信上下文字段，不要求用户在 query 中输入内部 ID。

评分器优先使用 predictions 中的 `current_round_calls` 报告当前轮计划覆盖、最短链成功、已覆盖计划额外调用和重复调用；累计 `calls` 仍用于整条 Observation Loop 的不安全调用扫描。旧预测没有 `current_round_calls` 时回退到 `calls`。真实 Dify 运行结果必须写入独立 predictions 文件，并保留 `workflow_run_id`；不得用金标生成满分预测冒充基线。

参数金标保留用户提供的自然名称或别名，由 Travel Core 在执行时解析规范 ID；工具间的数据依赖使用前序 Observation 返回的内部 ID，例如把 `poi.search.matches[].poi_id` 写入下一轮 `itinerary.build_draft.candidate_poi_ids`。工具 Schema 未要求、且省略后与显式默认值语义相同的可选参数，不写入金标。

数据集修订：`tool-calling-v1`。工具目录修订：`tool-catalog-v1.5`。
