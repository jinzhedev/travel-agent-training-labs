# Lab 04 路由、执行器与人工决定题集

本版对应 Lab 04 的最小 Chatflow：结构化请求、旅游／生活执行器、候选动作与 Human Input。无知识库依赖。`cases.jsonl` 是本版题目与预期的权威来源，使用新编号 L04，避免与旧 RTH 报告混用。

共 15 题：L04-001～014 用于 Phoenix 自动回归；L04-015 单独验证真实超时。自动回归中的人工决定由 runner 模拟提交，不等于有人完成了审批。学员仍需在 Web App 手工完成批准、修改、取消各一次。

字段说明：`input` 只包含发送给应用的 query；`expected` 是人工核对的评测约束；`human_action` 是测试驱动的模拟决定，不能传给请求解析 LLM；`mode` 区分自动回归与真实超时。

runner 将 query 放入 `/v1/chat-messages` 请求顶层，inputs 为 `{}`，每题不传 conversation_id，以新会话开始。人工决定通过表单提交并恢复原 workflow_run_id，不发送新的聊天消息。Answer 只展示最终状态 JSON；runner 从 `workflow_finished.data.outputs.answer` 解析结果。由 Workflow 切换到 Chatflow 不改变题目和金标，但需重跑基线，Experiment metadata 记录 `app_mode=chatflow`。

`expected.tasks` 检查 kind、city、date、utility_type、depends_on，任务 ID 只要求非空且唯一，不固定模型生成的编号。clarify / unsupported 题不评价模型在拦截前提取了多少任务，要求两个执行器均不运行。日期固定用于重复实验，天气、POI 与服务返回均为课程模拟结果，不作为实时出行依据。

生活工具当前返回模拟调用确认，没有真实缴费 URL。L04-007/008 的正确回答需要说明入口资料不足，不能凭模型记忆补网址，也不能把 `accepted=true` 解释为缴费成功。代码评分不判断这项答案语义，需对照工具返回人工检查。
